# B 画面裁剪覆盖

用途：看 A 的比赛画面，听 B 的解说，同时把 B 的摄像头区域覆盖到 A 上。覆盖的是持续播放的视频，不是截图，也不是独立的系统置顶窗口。

## 使用

1. 进入 A 直播间，从“解说源”选择 B，完成音画校准。
2. 在“解说设置”点击“裁剪 B 画面覆盖到 A”。
3. 在 B 的完整画面上拖出矩形选区。拖动四角和四边中点改变范围，拖动中心点移动选区；确认前不会覆盖 A。调整完点击“覆盖到 A 画面”，也可以选择整个画面。
4. 显示播放器控制栏后，拖动覆盖区域调整位置，拖动右下角调整大小。裁剪和关闭按钮也随控制栏隐藏。
5. “重新选区”可再次裁剪；关闭覆盖保留 B 声音。“再次校准”暂时显示完整 B 预览，结束校准后恢复裁剪覆盖。

位置、尺寸、选区仅保存在本次双流会话。全屏及普通窗口使用相对坐标，更换 B、切换 A 或退出双流后清空；同一 B 重连保留选区。

## 边界

- 与双流相同的平台入口；桌面鼠标操作为主要使用场景。系统原生画中画是否包含覆盖层取决于平台捕获方式，不作保证。
- B 的画面和声音来自同一个播放器，现有偏移同时影响两者；没有第三路拉流、单独的人脸延迟或人脸自动追踪。
- 默认沿用 B 的低清线路，裁出的小区域放大后可能模糊；本次未新增 B 清晰度选择。
- 这是显示裁剪：开启时仍需解码 B 的完整视频帧，不会只解码选区。关闭覆盖和校准预览后关闭 B 视频轨。
- 选区按 B 原视频尺寸归一化，不包含播放器补出的黑边。B 改变直播布局时需要重新选区。
- 双流期间仍不支持录制。覆盖层、编辑器、校准预览互斥渲染 B，避免多个视口争用同一视频输出。

## 2026-09-09 灰屏与退出崩溃回归

冻结基线：功能提交 `2e3cbccff2b8ff3efe1e325b2a0a2966d435a891`；本地已审查上游引用 `b97ed3ed628e6bf9dfacd96be3b4418da40eb966`，本轮不进行上游同步。

- 灰屏相关缺陷归类 `fork-regression`：裁剪覆盖组件缓存了 `getVideoWidget()` 的返回值。MediaKit 适配器在该 Widget 内创建单订阅尺寸流，切换裁剪/覆盖分支重新挂载它时会二次订阅。保留播放器实例，但每个挂载位置创建独立显示 Widget；不会重开直播或重置同步。回归替身现在包含单订阅流，而非只有空盒子。
- 用户还报告首次进入覆盖界面时底图变灰。尚无该次 Flutter 异常日志，不能把上述代码缺陷与用户所有灰屏路径直接画等号，仍需测试包实机确认。
- macOS 退出崩溃报告指向 `sqlite3_finalize → NativeFinalizer::RunCallback → RunAndCleanupFinalizersOnShutdown`。数据库服务没有显式关闭，窗口销毁也没有等待清理。增加数据库关闭入口及可等待的统一退出事务，先卸载页面订阅，再释放播放器、关闭数据库、落盘设置，最后允许系统退出。数据库原生问题的完整来源仍需进一步判定，不能仅凭退出堆栈归因于视频或 HDR。
- 菜单 Quit / ⌘Q 通过 Flutter 的 `onExitRequested` 等待清理，应用内关闭入口在销毁窗口前等待同一事务；重复退出请求和 B 的并发释放合并为一次。
- 不更改数据库结构，不清除配置或关注列表。回滚该批次代码即可恢复原行为，无数据迁移。

新增退出顺序测试：`test/desktop_shutdown_test.dart`。真实 macOS Quit、双路原生纹理及 Windows 包仍需对应平台验收；定向 Widget 测试不代表原生解码已验证。

本轮候选版本 `3.0.16+4104`。定向五文件共 25 项通过（约 13 秒）；反向恢复旧缓存写法后，同一裁剪→覆盖用例确定性报出 `Bad state: Stream has already been listened to`，恢复修复后通过。测试首次启动被本机回环端口权限拦截，授权后运行；另修正了一个浮点尺寸精确比较的测试断言。正式构建仍仅在 GitHub 执行，测试版尚未发布为正式 Release。
