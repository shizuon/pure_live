# Mac 解码模式测试

候选版本：3.0.20+4108。基于本仓库已发布的 3.0.19 及其发布索引提交 `1b6d95d1`；没有同步新的上游代码，也没有升级 MediaKit 或 libmpv。

## 怎么切换

设置 → 播放器内核设置 → **Mac 视频解码**。

| 模式 | 视频解码 | 画面输出 | 失败行为 |
| --- | --- | --- | --- |
| 软解（默认） | CPU，`hwdec=no` | 原有软件输出 | 保持 3.0.19 的兼容策略 |
| 硬解 only | VideoToolbox，`hwdec=videotoolbox` | 插件现有 OpenGL 硬件输出 | 禁止运行时软解回退；发现起播实际用了软解后暂停并报错 |
| 硬解兼容 | VideoToolbox 回拷，`hwdec=videotoolbox-copy` | 原有软件输出 | 允许回退到 CPU 解码 |

首次创建播放器前可以直接选择。播放器已经创建后，更改、导入或重置配置都只影响下次启动：需要**完全退出应用再打开**，仅关闭直播间或刷新不算重启。界面同时显示已保存选项与本次运行模式，避免把待生效设置当成当前状态。A、B 和多画面共用本次运行模式，不会在更换 B 时混用新旧配置。

旧版本没有这个设置，升级后仍使用软解。旧备份的 `enableCodec=true`、自定义视频驱动、硬解选项和 Android 兼容开关不会覆盖 Mac 的三档策略；自定义音频输出继续有效。Windows、Android、iOS 的解码设置和 UI 不变。

## 实际是否硬解

同一设置页有 **A / B 实际解码状态**，点击刷新读取当前快照：

- `videotoolbox`：实际使用直接硬解。
- `videotoolbox-copy`：实际使用回拷硬解。
- `no`：实际使用软解；硬解兼容模式也可能出现。
- B 仅播放声音时显示“仅音频／视频轨已关闭”，不是硬解故障。校准预览和裁剪覆盖打开视频轨后，才涉及视频解码。
- 没有直播、等待视频就绪、原生实例正在退出分别显示对应状态，不伪装成软解或硬解。

状态读取只在点击时进行，没有常驻轮询。硬解 only 额外监听原生解码器／视频参数的变化，合并检查任务，等待已有视频输出参数后才判断；换流、切音频、退出时使旧检查失效，退出释放监听与计时器。

mpv 的 `hwdec` 是请求值，不能用来证明实际硬解。`hwdec-software-fallback=no` 也不足以排除不受支持编码在起播时选择软件解码器。因此严格模式还检查 `hwdec-current`，发现实际软解后不继续播放。这个检查发生在解码器起播之后，**不保证起播过程中连一帧软件解码都没有发生**。选纯硬解不能增加芯片对编码格式的支持。[mpv 硬解选项](https://mpv.io/manual/stable/#options-hwdec)、[实际解码器属性](https://mpv.io/manual/stable/#property-list-hwdec-current)。

## 测试时看什么

建议先用玩机器直播间、同一画质／线路比较三档。切换模式后重启，每档记录实际解码器，再做以下测试：

1. A 单流：声音、画面；窗口、部分遮挡／操作别的 App、全屏往返。
2. 双流：B 仅声音、再次校准、九点裁剪、拖动／缩放覆盖、隐藏覆盖再恢复。
3. A/B 换房间、换清晰度／线路、暂停继续、B 失败恢复 A、完全退出。
4. HDR 屏幕：重点看硬解 only 的窗口闪烁／灰屏。若复现，改硬解兼容并重启；仍有问题则回软解。
5. 对照 CPU、声音连续性和画面卡顿。不要只看模式名称，也不要把短时间变化当成长期性能结论。

硬解兼容仍要回拷和软件图像转换；此前采样发现的 Swscale 开销不一定消失。硬解 only 开启的是插件现有 OpenGL 输出，**不是新增 Metal 或 HDR 渲染器，也没有保证零拷贝**。Flutter 现有关闭 Impeller 的兼容配置、视口尺寸优化和裁剪纹理生命周期均保留。

## 自动化验证边界

针对性测试覆盖三档参数、配置迁移／导入／重置／会话冻结、UI 选择与手动状态读取、B 纯音频、起播暂态、严格模式拒绝软解、检查任务取消／销毁，以及原有双流／裁剪／多画面／尺寸控制回归。

回归中发现既有交叉淡入淡出测试依赖固定 2050ms 等待：机器忙时可能尚未进入淡入淡出阶段就退出，测不到预期路径。已改为等待第一次真实音量变化后退出，不修改音频播放逻辑，也不放宽断言。

2026-09-12 本机合并回归：上述 11 个测试文件共 **80 项通过**，相关 Dart 文件静态检查通过。测试使用假播放器／原生属性替身，没有构建或启动本机应用，也没有更改用户的真实播放器配置。

应用包交给 GitHub Actions 构建。自动化测试不使用真实 VideoToolbox，不能证明特定直播编码能硬解、HDR 无闪烁、CPU 降低或长时间播放稳定；这些必须用测试包实测。本次不把候选自动设为正式 Release。
