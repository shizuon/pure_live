# Pure Live 双流同步与 macOS 播放修复

日期：2026-11-13。基础提交：`276d1ead2678d4ebfd66a48017af2f6dde52ca04`。本轮处理 macOS 上虎牙 CSBOY-Mo（蓝光30M、Line 1）配抖音玩机器CSGO的同步漂移与播放卡顿。

修复在本地 `3.1.3+4116` 候选构建上完成实播验证，正式交付版本为 `3.1.4+4117`。应用包含 Apple Silicon 与 Intel 两种架构，ad-hoc 深度严格签名校验通过。账号、收藏和原有应用数据保留。源码随 v3.1.4 发布。

## 修复内容

### 缓冲恢复保留同步基准

原逻辑在 A 流缓冲恢复时，将恢复瞬间的实际 A/B 时间差写成新基准，缓冲造成的新增误差随之进入目标关系。该逻辑由双流提交 `900646e8f8a51ff2bc9e00eefd64f6c0a0dc6c00` 引入，来源分类为 `fork-regression`。

现删除该次重新取基准和对应状态变量。A 缓冲时将 B 恢复到 1.0x；A 恢复后继续按原校准关系纠偏。既有每 2 秒检查、连续 3 次确认、0.98x/1.02x 微调和低缓存保护保持原语义。

回归覆盖 +12.8 秒校准后连续两次 A 短暂缓冲，检查偏移保留、继续纠偏、B 不重开、不重复施加暂停，以及误差恢复后回到 1.0x。

### macOS 帧交付异步化

原 `VideoOutput` 在纹理注册、尺寸更新及逐帧通知阶段同步等待主线程，主线程又可能正在等待 libmpv。该交叉等待链已存在于第三方插件引入提交 `41c8343`，来源分类为 `upstream-existing`。

现将主线程任务异步派发，每路最多保留一个待执行渲染更新，并合并尚未交付的帧通知。首次注册保留对象至注册结束，逐帧任务使用弱引用，原始 mpv 回调的主线程派发与释放边界继续保留。

原生回归直接编译生产 `VideoOutput` 和 `Worker`，覆盖 1000 次突发请求合并、主线程阻塞期间渲染任务继续推进、主线程通知，以及活动渲染期间关闭输出后的纹理注销。

### 修正硬解回退参数

原初始化使用 `hwdec-software-fallback`。应用内 libmpv 0.36.0 对该名称返回 `-8 / property not found`，使预期的硬解回退设置失效；错误名称在 `41c8343` 中已存在，来源分类为 `upstream-existing`。

现使用受支持的 `vd-lavc-software-fallback`：兼容模式写入 `1`，严格硬解模式写入 `no`。实际 `hwdec-current` 检查和发现异常软解时的暂停、报错继续保留。

独立探针直接加载已安装应用的 libmpv，创建未加载媒体的独立上下文：正确属性写入 `no`、`1` 均返回成功，分别回读 `no`、`yes`。探针未改动正在播放的上下文。完整结果见 `verification/mpv-software-fallback.json`。

### 补齐按需诊断

原有手动刷新诊断增加音频时间戳、AV 同步差，以及同步阶段、阶段耗时、待完成状态、请求/已应用偏移、时钟误差、漂移检查和主流重载状态。诊断按需读取，没有新增后台轮询。
