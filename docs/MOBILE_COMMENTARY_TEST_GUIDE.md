# 双流移动端测试包：怎么测

本轮为 `3.0.22+4110` 候选。云构建、附件和验证进度见 [实现记录](MOBILE_COMMENTARY_IMPLEMENTATION.md#云端交付记录)。编译通过不代表以下设备场景已经通过。

## 安装

- Android：取 `pure-live-android` 附件中的 arm64 APK；最低 Android 8。名称带 `test-signed` 的包使用云端临时测试证书，可能无法覆盖已安装版本。先在旧版导出设置和关注列表；不要直接卸载丢数据。
- iPhone/iPad：取 `pure-live-ios-self-sign` 附件中的 `ios-arm64-unsigned.ipa`，使用自己的签名工具处理后安装。目标最低 iOS/iPadOS 15.6；签名工具需要同时处理分享扩展和相关权限。不要把这个包当作已签名 IPA，也不用改拿 TrollStore 专用包。
- 解压 Actions 附件后，安装包旁边的 `.sha256` 用于核对下载完整性。

## 先测这五步

1. **单流正常。** 先单独打开 A，确认画面、声音、弹幕正常。再单独确认 B 可播放，并把 B 加入关注。
2. **启动与校准。** 回 A，通过“解说源”选在线 B。对照两路时间戳，分别试 `10ms`、`100ms`、`500ms`；连续点提前、延后，再反向调整。两路仍应有可核对的画面。正数延后 B 声音，负数让 B 声音相对 A 提前，后者靠暂缓 A 实现。
3. **校准后覆盖。** 先选好 B 画质，再校准；完成后进入裁剪，框选、用九点调整、确认并拖动覆盖块。进入裁剪和确认覆盖应保持同一个 B 播放实例，不应重新连接或清空偏移。主动更换 B 画质会重开 B，之后需要重新校准；默认高清不能保证所有平台都恰好提供“蓝光4M/8M”。
4. **再次校准与弹幕。** 覆盖后再次打开校准，修改偏移、完成，再返回覆盖。试切换 A/B 弹幕来源。选择 B 后，弹幕按当前可实现的延迟调度；负偏移不能提前显示尚未收到的消息。
5. **退出。** 退出双流应恢复 A 声音；换 A、退出播放页后不能残留 B 声音。反复进入、退出几次，确认没有叠音。

## 再测平台行为

- 手机旋转、平板分屏：两路比较画面和操作按钮应可见，裁剪手柄可触摸；放大系统字体后仍能滚动到操作按钮。
- 锁屏/后台：开启后台播放时听 B，关闭时两路暂停。返回前台后核对画面与声音，观察是否出现黑屏、偏移变化或重复声音。后台会关闭视频轨，恢复后会提示检查同步。
- 暂停后锁屏、来电或切其他 App：返回不应擅自播放；播放中来电、蓝牙切换再恢复时检查两路状态一致。
- Android 系统画中画：应显示 A 和已确认的 B 覆盖区域，回页面后还能继续校准。**本轮没有实现 iOS 系统画中画**；应用内覆盖区域是另一项功能。
- 持续播放：同平台及跨平台各试一组，稳定网络下播放约 30 分钟，记录是否逐渐不同步，以及发热或掉帧情况。约 200ms 漂移是待验证目标，不是已测结果。

## 有问题时记录

给出设备/系统、版本、A/B 平台与房间号、画质和线路，以及触发前最后几个操作。声音是否还在、只有 B 黑屏还是 A 也黑屏、偏移数值有没有改变尤其有用。截图可保留界面时间戳；日志中不要公开 Cookie、Token 或带鉴权参数的直播地址。
