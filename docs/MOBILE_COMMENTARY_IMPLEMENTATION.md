## 已实现的基础

### A 的直播恢复

直播起播后收到 EOF 或 network/source 错误，使用独立恢复协调器合并通知，按 1、3、8 秒进行最多三次恢复。每次重新取房间状态和签名地址，优先按稳定清晰度 ID 保留选档；线路列表重排时优先匹配原 CDN，后续失败再尝试下一条新线路。确认下播停止，未知状态作为可重试失败；连续稳定播放 30 秒后才重置预算。

恢复不重建弹幕和页面控制器，向 UI 发布新画质/线路列表，并通知双流重新建立基线。公开播放、暂停、切房和关闭都会使旧恢复失效；原生开流完成后也检查最新暂停意图。录播、时移和 IPTV 不走该直播恢复路径。

### 双流引擎会话

启动双流时确保 A 有同步能力。iOS 当前 A 使用 IJK 时，先静音准备 MediaKit，准备完成才切换 A 所有权；失败或退出取消则销毁候选，保留原 A 和音量。双流会话内禁止自动/手动切到不兼容引擎。退出解除约束，当前 A 保持连续；下次重载或换房使用原内核偏好，不写永久设置。

Android 兼容模式的 `mediacodec` 配置现在只在 Android 生效，防止从备份导入该开关后误用于 iOS。

### 系统音频

新增 `LiveAudioSessionState`：会话播放流、输出音量、用户播放/音量操作代次。双流对外报告会话状态，校准单独暂停一路不再误停系统媒体状态。音频中断按序处理：只有中断前播放且没有后续用户命令才自动恢复；duck 按原音量比例降低并恢复，用户在中断期间修改音量则保留新值。显式停止清除恢复意图。
