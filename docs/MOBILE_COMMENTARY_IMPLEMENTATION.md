## 已实现的基础

### A 的直播恢复

直播起播后收到 EOF 或 network/source 错误，使用独立恢复协调器合并通知，按 1、3、8 秒进行最多三次恢复。每次重新取房间状态和签名地址，优先按稳定清晰度 ID 保留选档；线路列表重排时优先匹配原 CDN，后续失败再尝试下一条新线路。确认下播停止，未知状态作为可重试失败；连续稳定播放 30 秒后才重置预算。

恢复不重建弹幕和页面控制器，向 UI 发布新画质/线路列表，并通知双流重新建立基线。公开播放、暂停、切房和关闭都会使旧恢复失效；原生开流完成后也检查最新暂停意图。录播、时移和 IPTV 不走该直播恢复路径。

### 双流引擎会话

启动双流时确保 A 有同步能力。iOS 当前 A 使用 IJK 时，先静音准备 MediaKit，准备完成才切换 A 所有权；失败或退出取消则销毁候选，保留原 A 和音量。双流会话内禁止自动/手动切到不兼容引擎。退出解除约束，当前 A 保持连续；下次重载或换房使用原内核偏好，不写永久设置。

Android 兼容模式的 `mediacodec` 配置现在只在 Android 生效，防止从备份导入该开关后误用于 iOS。

### 系统音频

新增 `LiveAudioSessionState`：会话播放流、输出音量、用户播放/音量操作代次。双流对外报告会话状态，校准单独暂停一路不再误停系统媒体状态。音频中断按序处理：只有中断前播放且没有后续用户命令才自动恢复；duck 按原音量比例降低并恢复，用户在中断期间修改音量则保留新值。显式停止清除恢复意图。

## 移动会话与紧凑画面阶段（3.0.22+4110 候选）

- Android 入口开放实验测试，与 iOS 使用同一 MediaKit 双流约束；桌面解码选项不改动。
- 应用级移动生命周期观察器区分可见、系统 PiP、完全后台。`inactive` 不触发关轨，避免通知中心或分屏焦点变化破坏仍可见画面。进入后台按既有后台播放设置决定继续声音或暂停两路；返回只恢复由该观察器造成且没有被后续用户操作覆盖的暂停。
- 完全后台关闭两路视频轨，继续播放时保留音轨、实例与地址；前台/PiP 恢复视频，不重新解析地址，也不再次暂停以重复应用旧偏移。关闭视频轨后的原生时间关系不保证不变，恢复会提示再次核对；这与前台隐藏校准/切裁剪保持视频轨的策略不同。
- 后台事务串行，并按会话代次隔离切房/退出；退出等待事务后恢复 A，确保后台没有 B 残留。来电及 duck 仍由此前会话级中断协调器处理。
- Android PiP、应用内悬浮窗接入已确认的 B 裁剪层，小窗不显示编辑手柄，也不改变原校准/编辑状态。播放图标取会话状态，不再只跟随校准时可能短暂停顿的 A。移动端拖动不再调用桌面 window_manager API。
- iOS 主应用、Podfile、分享扩展部署目标统一为 15.6；分享扩展只用 UIKit/Social，没有 18.2 专属 API。保持扩展功能及现有 Bundle ID，不导入签名凭据。云编译仍需验证最低版本兼容；unsigned/TrollStore 产物不等于普通设备直接可安装。
- 合并定向回归 43 项通过（后台状态、切轨、退出恢复、PiP 展示、触摸、引擎恢复、系统中断和原有校准）；首次紧凑 Widget 测试需等待 GetX 重建落帧，改用 `pumpAndSettle` 后通过。

### iPhone/iPad 自行签名安装包

用户选择自行签名。云端在 TrollStore 专用签名前独立生成 `PureLive-*-ios-arm64-unsigned.ipa`，以 `Payload/Runner.app` 打包；`pure-live-ios-self-sign` 附件包含 IPA 与 SHA256，即使后续 TrollStore 步骤失败也保留普通 IPA。交付前检查 ZIP 完整性、设备平台标记、主程序、Flutter/AOT 二进制与资源，不把结构校验等同于签名或设备验收。签名工具仍需处理嵌入的分享扩展及所用账号支持的权限。

Android 仓库目前未配置正式签名 Secrets。本轮显式选择 `android_test_signing=true`，只交付名称带 `test-signed` 的候选 APK，使用云端临时 debug 证书。该证书不保证跨构建一致，不能覆盖不同证书的旧包；测试前应导出数据。此选项禁止与 `create_release=true` 同用；正式发布仍要求原有正式签名配置。
