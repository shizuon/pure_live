# 第一批清理实验：设置、录制与 B 源解析

2026-09-10，基线 `e545d26e8aaee8db281e43cc124033e2e5edbff9`（3.0.18），候选 3.0.19+4107。

保留全部功能。E1—E4 分项提交；没有调整解码器、HDR 合成、直播缓存、原生媒体库或 Firebase。3.0.18 的卡顿候选修复保持不变。这一批验证的是减少了哪些调用、请求和后台任务，尚未测得整机 CPU、内存或帧率改善百分比。

## E3：状态与执行分离

[RecorderTaskStore](../lib/recorder/services/recorder_task_store.dart) 只从现有 Hive 设置读取任务，进行原有去重、平台有效性检查和状态恢复。录制按钮、双流录制冲突检查、录制中心共用同一份响应式任务列表。执行服务启动时不会用另一个快照覆盖界面中的任务。

没有新增持久化字段或迁移步骤。仅查看直播间不会把“上次进程退出时仍在录制”的标记覆盖到磁盘；执行服务仍负责恢复中断的文件处理、自动续录和保存。自动恢复受原有 `autoStartOnBoot` 设置控制，同一次服务生命周期只执行一次恢复。

恢复因临时权限或文件系统错误失败时，不缓存失败结果；下次显式使用可以重试。缓存扫描期间收到的检查请求合并为一次后续扫描，退出服务后停止追加工作。这两项有单独的回归用例。

缓存限制开启时，进入录制服务或打开限制会检查已有文件；有录制、排队、重连或合并任务时保留周期检查。任务结束并解除目录保护后再检查一次，避免短录制恰好错过一分钟周期。任务轮询、重连、输出监控和保护正在写入的目录均保留。

## E4：按需解析与取消

[候选游标](../lib/modules/live_play/service/stream_source_resolver.dart) 每次交付一条线路，同画质 URL 列表保留原顺序和请求头，跨画质重复地址只尝试一次。当前档请求失败或返回空列表，才继续下一档。

退出或更换 B 会取消旧游标。直播平台的 API 目前不能撤回已经发出的 HTTP 请求，因此该请求仍可能完成；它的结果会被丢弃，不继续解析其他画质，也不创建播放器。控制器先验证会话代次，再替换当前 B 的源，避免旧请求覆盖新房间。

重新同步和断线重连仍从房间详情重新解析，获取新的签名地址。不会因为改成懒加载而永久复用过期 URL。A 原声在 B 就绪前保留，校准、偏移、裁剪覆盖和 B 视频轨开关沿用原有逻辑。

## 合并前追加回归

以 fork 主分支 `353c9f35843bfeb35b972cbd40cd218c1385a6f8` 与候选 `94429823be479ac3a1a2ba06dc1327080150dbf3` 核对待合并的九个提交；主分支是候选祖先，没有额外分叉。用户已授权验证后合并至实际默认分支 `master`，不新增上游同步。

检查 B 取消链时发现旧稳定性等待的异常处理缺少会话检查：旧 B 被替换后，100ms 轮询发现会话失效并抛出取消异常，外层却把它当作线路失败，继续恢复 A 音量、释放当前 B。此时当前 B 已可能属于新会话。该缺陷在上述主分支已经存在，属于本 fork 双流功能的 `fork-regression`，不是 E4 懒解析新增。

新增测试以播放器事件控制时序，在旧 B 进入稳定性等待后创建新 B，再等待旧任务结束。原实现确定性失败：新播放器已被释放。修复在取消异常处理及恢复 A 音量后验证会话代次，旧任务直接结束；不再触碰新 B，不改变正常线路回退或稳定窗口。该测试与现有 URL 解析取消测试覆盖不同阶段。追加修复后，一次定向回归共 31 项通过，包含双流控制器、候选游标、偏移计算、裁剪布局、录制懒加载和设置注册；新取消测试是此前 54 项之外的新增覆盖。无数据迁移，可单独回滚这次取消保护提交。

GitHub Mac 打包校验追加 `unzip -tq` 与 `hdiutil verify`，检查 ZIP/DMG 内容完整性后才上传。修复后的最终候选需重新通过完整云质量门禁、Windows 构建和独立下载安装检查，以及 Mac 构建和包校验后才能合并；此前候选的检查不能代替新源码的检查。

## 来源与边界

冻结上游参考：`b97ed3ed628e6bf9dfacd96be3b4418da40eb966`。E1 的重复生命周期、E2 的桌面预热和 E3 的进房录制依赖/常驻计时器在该上游已存在，分类为 `upstream-existing`。E4 属于本 fork 自有双流功能的实现冗余，分类为 `fork-regression`；不把它归因给直播平台。

完整双平台编译和测试包由 GitHub Actions 完成。单元/Widget 测试不验证真实磁盘录制、系统权限、CDN 时延或播放器的原生初始化成功率。安装包需重点测试：第一次录制、监控开播、录制停止/合并、重启自动恢复、已有缓存限制、B 最低档失败后的跨档回退，以及快速更换 B。

## 比较和回滚

四个实验各有独立提交，可分别回滚；E3 的任务存储、界面和执行服务改动需作为一个整体回滚。比较单项收益时，从上述同一个 3.0.18 基线仅应用该项提交，用相同媒体、窗口和弹幕条件测试；不要把组合包相对旧版的变化分摊给每个实验。

这批没有更改数据格式，回退 3.0.18 不需要逆向迁移。出现首录失败、任务状态丢失、自动恢复失效或双流取消后残留声音时，回滚对应实验。
